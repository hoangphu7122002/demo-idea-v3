# Demo script — angle: wow-first (≤120 s)

Core job: A solo AI author can see which paragraphs a new release makes wrong, without rereading every post.
Framing: author's own need (decision.md risk 1); no "validated demand" claim.

| # | Beat | s | On screen | Script |
|---|---|---|---|---|
| 1 | Hook (flash end) | 15 | 2 s flash: post with 3 red "may be outdated" spans + source chips, badge flips to green "Verified". Freeze → W1 quote card E094 | "This is my post one minute from now. And this is why: 'A lot of it doesn't hold up anymore… but there's genuinely content I wrote years ago that I still find faultless.' (r/technicalwriting, E094). Which parts? Let's rewind." |
| 2 | Today | 15 | Rewind wipe → same post on Hugo + Giscus: correction buried in a bottom-of-page comment, body unchanged | "Today: static blog, comments at the bottom. A release lands, the post silently goes wrong, and I'd have to reread everything to find where." |
| 3 | Core action | 45 | Author view → paste real release note URL/text → click "Check against release" → spinner → paragraphs light up | "One action: I paste the actual release note and hit Check. It compares each claim in my post to the release — live Claude call, cached fallback." |
| 4 | Wow | 30 | 3 exact paragraphs highlighted red, each with reason + release-note source link; accept a pending reader suggestion on one → text rewrites, changelog diff + contributor credit appear, badge flips to "Verified" (the frame from beat 1) | "Exact paragraphs, the reason, the source line. A reader already suggested a fix here — accept, diff logged, credit kept, badge back to Verified. That's the frame you saw first." |
| 5 | Next | 15 | Later list as roadmap slide | "Next: watch release feeds automatically, re-check all posts nightly, reader OAuth suggestions at scale, deploy." |

Total: 120 s. Impact lands at 0–2 s (flash) and 75 s (payoff).
